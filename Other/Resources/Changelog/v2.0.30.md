# Release notes

## Changes

- fix
- `Misc.Captcha.CaptchaManager` consumes a captcha now: `TrySolve` removes it from the store regardless of whether the attempt succeeded. Before this a solved pair of captcha-id and answer stayed valid until the captcha expired (ten minutes by default), so it could be replayed for as many registrations or login-attempts as wanted, and a wrong answer could be guessed by repeating the attempt with the same id. A further attempt requires a new captcha now.
- `Misc.Captcha.CaptchaManager` removes its expired captchas and access-keys. Neither of the two collections was ever cleaned up before (the constructor said so itself), so both only grew - a visitor of a page which shows a captcha creates an entry with every call, which made this a slow memory-exhaustion any anonymous client could drive. The cleanup happens on access, so the object still needs no lifecycle, and it is throttled to at most once per minute so that the cost of a request does not grow with the amount of the stored items.
