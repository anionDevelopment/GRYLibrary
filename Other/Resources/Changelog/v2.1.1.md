# Release notes

## Changes

- Fixed DatabaseStructureDiagramGenerator for MariaDB: every primary-key-column was listed once per table of the database
  (for example "Hash" appeared 7 times in the entity "Transaction") and every foreign-key was drawn to every table of the
  database instead of to the referenced one. The reason was that MariaDB names the primary-key-constraint of every table
  "PRIMARY", so joining information_schema.TABLE_CONSTRAINTS respectively information_schema.REFERENTIAL_CONSTRAINTS to
  information_schema.KEY_COLUMN_USAGE by constraint-name matched the constraints of all tables. The schema-queries are
  engine-specific now (MariaDB reads COLUMN_KEY, REFERENCED_TABLE_NAME and REFERENCED_COLUMN_NAME directly and therefore
  does not need any join), and MariaDB only reads the schema of the currently connected database.
- DatabaseStructureDiagramGenerator ignores duplicated rows of information_schema now, so a column or a relation can not
  occur more than once in the generated diagram anymore.
- The plantuml-content generated by DatabaseStructureDiagramGenerator is deterministic now: tables, columns and relations
  are sorted by an ordinal string-comparison (instead of a culture-dependent one) and the lines are always separated by a
  line-feed (instead of the line-separator of the current operating-system).
- DatabaseStructureDiagramGenerator throws a NotSupportedException for Oracle-databases now, because Oracle does not
  provide an information_schema.
- Updated Swashbuckle.AspNetCore from 10.2.1 to 10.2.3, which is the version used by the products which consume this
  library; the difference made a project-reference to this library fail with a nuget-version-conflict (NU1107).
