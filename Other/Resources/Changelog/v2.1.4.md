# Release notes

## Changes

- Each finding of the "OWASP-Top-10-analysis"-section in the readme now carries a "Fixable without breaking changes"-line. It
  states for every one of the 37 findings whether it can be remediated in a way which is definitely not a breaking change for a
  consumer (no behaviour-change when the library is used as intended, no additional configuration required and no
  interface-change), as "Yes", "No" or "Partial", with a short reason.
- Each finding of that section additionally carries a "State"-line ("open", "fixed" or "accepted") which records how the finding
  is currently handled. The same value is reflected in the "Status"-column of the summary-table.
- Remediated the breaking-change-free security-findings of that section (no behaviour-change for a consumer who uses the library
  as intended):
  - GRY-09: removed the referenced but unused `System.Data.SqlClient`-package.
  - GRY-10: set `NuGetAuditMode` to `all` and promoted the audit-warnings `NU1901`-`NU1904` to errors, so a known-vulnerable
    dependency now breaks the build of this library.
  - GRY-12: added `Crypto/PasswordHasher`, a password-hashing-primitive on PBKDF2-HMAC-SHA256 with a per-password salt, a stored
    iteration-count and a constant-time verify (including unit-tests). The non-working `Argon2`-stub was kept.
  - GRY-15: the migration-table-name and the migration-name are now validated against a strict pattern before they are
    interpolated into a migration-statement.
  - GRY-22: marked `OIDCService.LoginWithPasswordAsync` (the resource-owner-password-credentials-grant) as `[Obsolete]`.
  - GRY-25: removed the discarded `GetUserByAccessToken`-lookup in `AuthenticationMiddleware.IsAuthenticatedInternal`, which also
    stops the spurious exception on the oidc-bearer-path.
  - GRY-27: the oidc-authorization-code-flow now sends a `nonce` and returns it in `OIDCAuthorizationRequest.Nonce`, so a consumer
    can compare it against the id-token-claim the same way it already verifies the `state`.
  - GRY-29: documented that the assembly is strong-name-signed by the build-pipeline when it is released (the repository carries
    only the public key for delay-signing).
  - GRY-33: `AuthSMiddleware` now logs the previously swallowed authentication-exceptions at debug-level (the fail-closed
    behaviour is unchanged).
  The findings GRY-17 and GRY-28 were classified as breaking-change-free as well but deferred, because they are larger additive
  features; they stay "open".

## Remediated security-findings which need an action when upgrading

- GRY-11: the reference `TransientAuthenticationService` now hashes passwords with the new `PasswordHasher` (PBKDF2-HMAC-SHA256,
  per-password salt, constant-time verify) instead of an unsalted single-round SHA-256, and `Login` verifies through it.
  Required action: password-hashes produced by the previous `Hash` (hex SHA-256) are not compatible with the new verification,
  so stored passwords have to be re-set (or the users re-created). A consumer which copied the old hashing into its own
  authentication-service should switch that service to `GRYLibrary.Core.Crypto.PasswordHasher` as well.
- GRY-23: `OIDCService.ValidateAccessTokenAsync` now requires `OIDCProviderConfiguration.Audience` and throws an
  `InvalidOperationException` when it is not set, instead of skipping the audience-check. Required action: set `Audience` for
  every OIDC-provider which is used to validate incoming access-tokens (otherwise access-token-authentication throws). This does
  not affect id-token-validation. There is deliberately no opt-out.
