# Release notes

## Changes

- `ExternalProgramExecutor.Terminate` now really ends the executed program and every program which was started by it.
  It called `Process.Close` before, which only releases the handle of the process, so a program which was executed
  asynchronously kept running although the caller asked for its end.
- `ExternalProgramExecutor.Dispose` now ends the executed program if it is still running. It did nothing before, so a
  program which was executed asynchronously outlived the `using`-block which executed it.
- The execution of a program which is executed asynchronously is now completed when the program ends. Before that
  `IsRunning` stayed true for ever, `ExitCode`, `ExecutionDuration`, `AllStdOutLines` and `AllStdErrLines` never became
  available, `ExecutionFinishedEvent` was never raised, a configured `TimeoutInMilliseconds` was ignored and the thread
  which logs the output of the program never ended.
- the readme contains a section "OWASP-Top-10-analysis" which records the result of a security-analysis of the library against the OWASP Top 10:2025. The focus of the analysis is the api-server with its middlewares, its authentication- and authorization-services, its openid-connect-implementation, its request-logging and its data-access-layer, because those are the parts which a consumer of the library really exposes. It documents 37 findings with their evidence, their impact, a mitigation-proposal, a criticality, a confidence and a status, followed by a prioritized remediation-plan and a summary-table. The critical one is the unsalted single-round sha-256-password-hash of the reference authentication-service, which every consumer copies; the high ones are the opt-in authentication (a route without an attribute is public), the authorization which re-reads the token without re-validating it, the missing usable password-hashing-primitive (the argon2-class throws), the synchronous-over-asynchronous pipeline, the rate-limiting which can not be switched on at all, the openid-connect-audience which is validated only when it happens to be configured, the openid-connect-principal which does not carry the issuer, and the request-logging which writes the access-token of every login into the log-file
