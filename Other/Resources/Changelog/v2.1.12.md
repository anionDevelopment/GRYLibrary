# Release notes

## Changes

- Fixed `ExternalProgramExecutor.CreateEpewArgumentString`: the generated argument-string contained arguments which Epew rejects, so the generated command-line could not be executed by Epew. The log-file is now passed as `--LogFile` instead of `--Logfile` (the parser of Epew is case-sensitive), and `--ThrowErrorIfExitCodeIsNotZero` is not generated anymore, because Epew has no such argument (Epew returns the exit-code of the executed program, so the caller of Epew decides how to handle a non-zero exit-code).
- Added `HostMaintenanceRoutes.RoutePrefix` to host the maintenance-routes under a configurable path-prefix (for example `/MyApp/API/Other/Maintenance/HealthCheck`)
- If `TrustForwardedHeader` is enabled, the client-ip-address is now taken from the last entry of the `X-Forwarded-For`-header, which is the one appended by the trusted reverse-proxy (before, a header with several addresses caused an exception and the address could be spoofed by the client)
- `OIDCService` now requires https: the `Authority` of an `OIDCProviderConfiguration` and the `authorization_endpoint`, `token_endpoint` and `jwks_uri` from the discovery-document must be absolute https-urls, otherwise an `InvalidOperationException` is thrown before any request is sent to such an url (before, a plaintext-authority or -`jwks_uri` allowed an attacker on the network-path to replace the signing-keys and forge tokens). Migration: configure the authority with https, also for local providers.
- The health-check now reports `Degraded` instead of `Healthy` while the service is initializing (consistent with the state before the initialization), so that consumers which only route traffic to `Healthy` instances do not route requests to an instance whose initialization (for example a database-migration) is still running.
- Added the attributes `PreventRequestBodyLog` and `PreventResponseBodyLog` for controller-methods. If a controller-method has such an attribute, the `DRequestLoggingMiddleware` does not log the request-body respectively the response-body of this method, regardless of its configuration. Use them for example for login-, token- or password-related routes instead of the route-based `RoutesWhereRequestBodyIsNotLogged`/`RoutesWhereResponseBodyIsNotLogged`-configuration, because an attribute is bound to the controller-method and does not break when a route is renamed.
